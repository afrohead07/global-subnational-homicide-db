# Output format for all country pipelines (homicide_format 1.2)

Generated by `python homicide_format.py spec`; the validator enforces exactly this.

## Folders

```
<repo>/Pipelines/homicide_format.py            (this module: format, folder layout, downloads, validator)
<repo>/Pipelines/<Region>/<country>_homicide_rate.py  the pipeline
<repo>/Pipelines/<Region>/<country>_homicide_rate.csv its ONE output
<repo>/Data/Raw/<Region>/<Country>/                   every download of that country, date-stamped
```

- `<Region>` is Asia, Americas or Europe; the folder the script sits in decides where its downloads go.
- **One output per script**: exactly one CSV. Diagnostics are printed, never written; anything else a script keeps (cached downloads) lives in its country's raw folder. No probe, helper or comparison scripts or files stay in `Pipelines/`.

## Files

- Script and output named `<country>_homicide_rate.py` / `<country>_homicide_rate.csv`, lower case with underscores (`south_korea_homicide_rate.csv`). A source that covers several countries is named after the source (`eurostat_homicide_rate.py`, raw files in `Data/Raw/Europe/Eurostat/`) and its `country` column carries the country.
- CSV: UTF-8 **with BOM**, comma separated, one header row, `.` as decimal separator, no thousands separators, booleans `True`/`False`, empty cells instead of `NA`/`nan`/`None`, no line breaks inside cells, rows sorted by (country, parent_unit, unit, year).
- Downloads go through `F.Fetcher`: robots.txt respected, each file saved as `<name>_<YYYYMMDD>.<ext>` in the country's raw folder and logged with its sha256, TLS certificates verified (turning that off needs an explicit `insecure=True` and prints a warning). `retrieved` is the date of the data actually used.
- Nothing is typed in by hand: every number comes from an official file read by the script.

## Columns (fixed order; country-specific extras go after them, in lower snake_case)

| # | column | type | required | meaning |
|---|---|---|---|---|
| 1 | `country` | text | yes | Country name in English, e.g. Japan. |
| 2 | `unit` | text | yes | Area name in English as the source gives it (else a standard transliteration). Unique within (country, parent_unit). |
| 3 | `unit_local` | text | no | Name in the local script, only when the source provides it. |
| 4 | `unit_code` | text | no | The country's own official code for the area, kept as text (leading zeros preserved). Never ISO codes. |
| 5 | `admin_level` | vocab | yes | admin1 = first-level division (province, prefecture, region, municipality, SAR); admin2 = second level (district, county); city = a city-level unit; police_unit = a police administrative unit that does not follow admin boundaries. |
| 6 | `unit_type` | text | yes | The source's own term in lower snake_case: province, prefecture, region, municipality, special_administrative_region, district, ... |
| 7 | `parent_unit` | text | no | Enclosing first-level area for admin2/city units (e.g. the state of a Malaysian district); blank otherwise. |
| 8 | `year` | int | yes | Calendar year the count refers to. |
| 9 | `homicide_cases` | int | yes | The count (>= 0) in the unit defined by indicator_type and definition_flags: recorded cases, deaths or convictions. |
| 10 | `population` | int | yes | Denominator actually used, in persons (>= 100,000); how it was built is in population_method. |
| 11 | `homicide_rate_per_100k` | float | yes | homicide_cases / population x 100,000, not rounded. |
| 12 | `flag_low_count` | bool | yes | True when homicide_cases < 10. |
| 13 | `flag_outlier_year` | bool | yes | True when the year's robust z-score within the unit's own series exceeds 3.5; only tested for series of >= 8 years, otherwise False. |
| 14 | `indicator_type` | vocab | yes | police_recorded_cases | health_registry_deaths | court_convictions. |
| 15 | `reliability_tier` | vocab | yes | A | B | C - how strongly the numbers were verified (definitions below), not how close they are to a perfect homicide measure. |
| 16 | `definition_flags` | flags | no | Semicolon-separated, only what the SOURCE states: includes_attempts | includes_manslaughter | counts_victims. Blank means 'nothing stated', not 'no'. |
| 17 | `validation` | text | yes | The checks this row passed, written by the script from computed values. |
| 18 | `indicator` | text | yes | What the numerator is, in the source's own terms. |
| 19 | `population_method` | text | yes | Source, reference date and averaging used to build the denominator. |
| 20 | `population_age_years` | float | no | How old the denominator is: years between the date the population refers to and the middle of `year` (1 July). 0 for a population of the same period (a mid-year estimate, the mean of two year-ends or of two 1 Januaries); 3.0 for a census taken three years before the count; blank only if the source gives no reference date. Tier A needs a value here that is at most 3.5. |
| 21 | `data_notes` | text | no | Caveats specific to the unit or year. |
| 22 | `source_homicide` | text | yes | URL(s) of the numerator source, semicolon-separated. |
| 23 | `source_population` | text | yes | URL(s) or table identifier of the denominator source. |
| 24 | `retrieved` | date | yes | YYYY-MM-DD on which the data was downloaded. |

## Vocabularies

- `admin_level`: admin1, admin2, city, police_unit
- `indicator_type`: police_recorded_cases, health_registry_deaths, court_convictions
- `reliability_tier`: A, B, C
- `definition_flags`: includes_attempts, includes_manslaughter, counts_victims

## Reliability tiers (verification strength)

- **A** - Every count reconciles to the source's own totals (or an equivalent identity) AND is confirmed by at least one independent check (a second edition, table or file, or an identity linking the denominator to another official figure), AND the denominator is no older than 3.5 years (population_age_years).
- **B** - Reconciled, with a documented weakness: read by OCR, confirmed by one source only, an unallocated remainder, a rounded or provisional denominator, a denominator older than 3.5 years, or a newest year read once.
- **C** - A check failed or could not be run, or the indicator is a proxy (health deaths, convictions). Not for headline use.

## Rules the validator enforces

- All core columns present, first, in order; no ISO-code columns.
- `year` whole number; `homicide_cases` whole number >= 0; `population` whole number >= 100,000.
- `homicide_rate_per_100k` = cases / population x 100,000 (relative tolerance 1e-09).
- `flag_low_count` = (cases < 10); flags are `True`/`False`; vocabularies respected; `retrieved` is `YYYY-MM-DD`.
- Required columns never empty; no leading/trailing spaces, line breaks or null words in any cell.
- `(country, parent_unit, unit, year)` is unique.
- `population_age_years` is a number >= 0 or blank; tier A needs it present and at most 3.5 (an unknown or older denominator is tier B at best).
- Warnings (not errors): unsorted rows, year gaps, population moving more than 25% in a year, rates above 50.

## Conventions for every script

- Commands `inspect` (checks, no file written) and `build` (writes the one CSV).
- Every table is reconciled against its own totals or an equivalent identity; a failure stops the unit (or skips the year, with a warning, where the source's own table does not add up).
- Decisions are named constants marked `# DECISION`; no statistic is ever typed into code or into a message.
- Shared constants (low count 10, minimum population 100,000, outlier z 3.5, minimum series 8) live only in `homicide_format.py`.
- Text columns are in English; local-script names go in `unit_local` only.
